Product Overview

Dual‑side architecture. One unified mission.

AccessReady follows a dual‑side product architecture: a lightweight student‑facing interface accessible via mobile and web browsers, paired with a role‑based, secure university‑admin management dashboard.

Designed specifically for higher‑education contexts rather than general public navigation, the platform unifies three core capabilities — personalised accessibility navigation, crowdsourced barrier incident reporting, and full‑cycle university maintenance management.

All modules interoperate as one integrated system, closing the historical gap between student on‑campus experiences and institutional facility‑management workflows.

Student‑Facing Side

Core basic features for students.

Everything mobility‑impaired students need to navigate campus safely and independently.

Personalised Route Navigation

Users select their own mobility profile before route calculation; the system generates accessibility‑adjusted routes instead of default shortest‑path directions.

  • Manual wheelchair user profile
  • Crutch / walking‑aid user profile
  • Temporary lower‑limb injury profile
  • Accessibility‑prioritised routing
  • Not just shortest path — safest path

Real‑time Facility Status

Instant lookup for key campus accessibility facilities — ramps, accessible elevators and accessible restrooms — with verified availability status.

  • Verified availability status per facility
  • Check conditions before departure
  • Ramp accessibility info
  • Elevator operational status
  • Restroom accessibility details

Crowdsourced Barrier Reporting

Geotagged barrier reporting with optional photo attachments and short descriptions. Reports saved as drafts when offline for later submission.

  • Geotag location marking
  • Photo attachment support
  • Short written descriptions
  • Local draft saving (offline)
  • Public progress tracking after submission

How It Works

The closed‑loop workflow.

Six connected steps that turn student reports into real campus improvements.

1

Select Mobility Profile & Generate Route

Users choose their mobility profile — wheelchair, crutches, temporary injury — and the system generates a personalised accessibility‑adjusted route instead of a default shortest path.

2

Submit Geotagged Barrier Report

When students encounter barriers, they submit reports with location marking, optional photos and short descriptions. Reports can be saved as drafts if network is unstable.

3

University Staff Verify Report

Designated university staff review submitted incidents — verifying location, severity and category before the report becomes an official maintenance ticket.

4

Traceable Ticket Created & Prioritised

Valid reports auto‑generate digital maintenance tickets. Administrators set multi‑level priority based on barrier severity and assign to the right team.

5

Maintenance Task Executed

Maintenance teams receive work orders with clear location data, photo evidence and priority marking. Task progress is tracked at every stage.

6

Map Updated & Loop Closed

After completion, the platform updates public map routes and facility status information. Students see resolved issues and the full‑cycle workflow closes.
